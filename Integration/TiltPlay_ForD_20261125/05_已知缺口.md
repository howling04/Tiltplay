# 已知缺口（演示前必读）

这些不是"待修 bug"，而是**现在就是没有/不能做**的东西。知道它们，演示时就不会被当成故障。

## 1. 回中（R 键）

| 项 | 现状 |
|---|---|
| 屏幕回执 | **没有**。按 R 成功或被拒，界面无任何提示。只能看 `TiltDump` 或网关日志的 `CENTERED` / `NOT_STILL` |
| 平放要求 | **必须平放（±10°）**。手上拿着板子按 R 一定不生效，这是门控设计，不是坏 |
| 重复一致性 | **未验证**。40 秒复测里只回中过一次；"按两次零点是否一致"没有数据。同一块板两次平放的读数本身差 3.7° |
| 松手回 0 | **未验证**。放下不等于自动回 0，必须按 R；回位段实测停在 +4° / +20° 都出现过 |
| 左倾 | **未测过**。所有验证只覆盖前倾和右倾 |
| reject 计数 | 每次按 R，网关回的 `control_ack` 会被插件当成"非 input 包"计入 `RejectedFrames`。不影响移动，但数字会虚高 |

## 2. 输入流

| 项 | 现状 |
|---|---|
| 失效判定 | 250 ms 无新帧即 stale，角色**立刻停**。这是设计，不是卡顿 |
| 重复采样 | 40 秒数据里 23% 的帧 `source_seq` 与上一个输入帧相同（60 Hz 输出里约 46 Hz 是新数据）。不影响观感 |
| 落盘丢失 | 复测那次 `bridge_stop` 记 2427 帧、落盘 2393（丢 1.4%），仅影响录制分析，不影响实时输出 |
| 延迟 | 前倾斜坡段，网关输出相对真实加速度角滞后约 **340 ms**（来自 `tau_s=0.5` 互补滤波）。慢慢倾倒能感觉到"慢半拍" |
| 双轴归一 | 前后和左右同时偏转时，`clamp_vector` 会把合矢量归一到 1，所以两轴同时打满时单轴达不到 1.0 |

## 3. 玩法层（D 自己的事）

- 插件只给 `move`（-1…+1）和事件；**移动速度、加速度、惯性、刹车力度全是玩法参数**，插件不提供。
- 按钮跳跃关闭。上下手势在本修正版已开启，是独立的 vertical_step_enabled，不由 button_jump_enabled 控制。UE 默认自动 ConsumeVerticalStep 并回确认，D 绑定 OnVerticalStep；若关闭自动消费，才由玩法手动调用消费。网关待发事件确认、过期或失效后清除，不会无限重发。
- 前倾 = 前进 这个方向定义，是 C 按"前端下压=往前"取的，最终由 D 拍板；如果 D 要反过来，改 `bridge.json` 的 `forward_output_sign` 即可（`-1` ↔ `1`），不用改代码。

## 4. 未打通的

- **MQTT 链路**：`bridge.json` 里保留了配置（已指向 `127.0.0.1`），本包走 USB 直连 + `with_mqtt=False`，MQTT 未参与演示，也未做性能复测。
- **UE 打包 exe**：今天这包不含；明天单独发（581 MB，需网盘/U 盘）。exe 里参数写死，不能改手感。
- **UE 侧对 invalid 的短容忍**：现在拿到 `valid=false` 就 `StopMovementImmediately()`，250 ms 才恢复。演示时链路一抖会看到"顿一下"。

## 5. 环境相关的坑（踩过）

- 串口监视器不关，网关打不开 COM 口（报"无法打开串口"，会列出可用串口）。
- `device_id` 不是 `nano-a1b2c3d4e5f6` 时，UE 当错误设备丢弃（`reject` 涨、`valid=0`）。
- PIE 多开会抢 7001，第二个客户端绑不上。
- `.cmd` 里不要写中文（Windows 会按字节拆断）；本包脚本全是纯 ASCII。
